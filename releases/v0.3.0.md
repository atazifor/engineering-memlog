# engineering-memlog v0.3.0

This release packages the work merged after 0.2.0: failure-triggered recall
after Bash output, a host-neutral Agent Skill and Agent Plugins manifest, Codex
skill packaging, and a dated agent-support matrix. See
[CHANGELOG.md](../CHANGELOG.md) for the full list.

## Fixed: duplicate failing hooks in Claude Code

Between 0.2.0 and this release, the plugin kept a Codex hook manifest at
`hooks/hooks.json`. Claude Code loads that path in addition to the hook file
named in `.claude-plugin/plugin.json`, and does not set the `${PLUGIN_ROOT}`
variable the Codex manifest uses. Every Claude session therefore ran a second
copy of each hook against `/hooks/...`:

```text
PostToolUse:Bash hook blocking error from command: "python3 "${PLUGIN_ROOT}/hooks/post-tool-recall.py""
can't open file '/hooks/post-tool-recall.py': [Errno 2] No such file or directory
```

The Claude hooks kept working, so recall was not lost. The Codex manifest now
lives at `hooks/codex-hooks.json`. A regression test requires that Claude Code
loads exactly one hook manifest and that it uses only Claude Code placeholders.

Codex no longer discovers the hook manifest by convention. Codex automatic hooks
had not produced context in live evaluation by either discovery route (see
[the Codex hook evaluation](../evals/codex-hooks.md)), so no working Codex
behavior is removed.

## Upgrade

```text
claude plugin marketplace update engineering-memlog
claude plugin update engineering-memlog@engineering-memlog
```

Then start a new Claude Code session.
