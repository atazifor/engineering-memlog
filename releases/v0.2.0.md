# engineering-memlog v0.2.0

This release turns Memlog from a write-mostly incident log into a debugging loop
that recalls prior lessons at the point of failure.

## Highlights

- `debug-with-memlog` gives Claude Code a systematic reproduce → recall → test →
  verify → preserve workflow.
- Ranked retrieval favors entries that cover the actual failure fingerprint,
  while stale or merely similar entries remain untrusted hypotheses.
- The plugin now bundles the CLI. Plugin users can search and append without
  cloning this repository or running `make install`.
- New entries have UUID-backed IDs and schema version 1; `memlog validate` checks
  corrupted rows and duplicate IDs without modifying the store.
- JSONL remains the private, zero-configuration default. A small provider
  protocol can connect another datastore or cache without changing the skill,
  hooks, validation, or ranking behavior.

## Debugging behavior after a miss

A successful empty search is not a dead end. The skill runs at most one exact
query and two evidence-derived broader queries, then continues with recent-change,
configuration, version, and data-flow inspection. It consults primary docs or the
web when the remaining uncertainty is external. Backend failures follow the same
local-diagnosis path but are reported distinctly and never trigger a fallback
store.

## Upgrade

Refresh the marketplace, update the installed plugin, and restart or reload
Claude Code:

```text
claude plugin marketplace update engineering-memlog
claude plugin update engineering-memlog@engineering-memlog
```

Existing JSONL entries remain readable as legacy schema version 1 records. The
provider feature is opt-in; no configuration change is required to keep using the
default file.
